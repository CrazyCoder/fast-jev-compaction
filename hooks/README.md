# JetCompact Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results a fast decision model
judged no longer needed: TypeSafe's Jev by default, or OpenAI's Decisions API
(`provider: "openai"`). Below, "Jev" stands for whichever provider is set.
`hooks/jetcompact.ts` is a thin adapter: it reads the plugin options, finds the
provider's key, hands `session.compact` transcripts to the `jetcompact` library
in `src/` (the plugin folder is the repository root, so the hook imports it
directly) and maps the result back onto session messages. User and assistant
prose in the recent turns is never touched; only host-generated blocks (system
reminders, task notifications, command echoes, hook output) outside the pinned
messages are cut to a head and a marker (`trimHostText`). Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. In the
default `rank` mode the best-scored results are kept verbatim within
`keepResultTokens`, then the best-scored calls keep their input and a truncated
result within `keepCallTokens`; with `keepMode: threshold` an item is kept when
Jev's probability reaches `keepThreshold`. A dropped result is truncated to its
first `truncateHeadChars` characters plus a one-line note, and a dropped call
leaves a stub (`dropCalls: false`, the default) or disappears with its result
(`dropCalls: true`).

The state is fitted into `maxStateTokens` in stages: tool inputs are truncated,
then long texts are abridged (oldest first, pinned messages last), then old
messages collapse to a `[… N chars omitted …]` note, then old tool calls shrink
to one line each, then old call-less messages are left out and runs of old
call-only messages fold together. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated without
a tokenizer, calibrated to land a little above what Jev reports.

The mod is an early-access Claude Code function-hook module. The checked-in type
reference was generated by Claude Code **2.1.292**. Enable the function hooks
surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add CrazyCoder/jetcompact
claude plugin install jetcompact@crazycoder
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in `.claude-plugin/plugin.json`:

| Option | Default |
| -- | -: |
| `provider` | `jev` (`openai`, `algorithmic`) |
| `recall` | `true` |
| `sessionIndex` | `auto` (`off`) |
| `model` | `jev-latest` (`gpt-6-luna` with `openai`) |
| `keepMode` | `rank` |
| `keepThreshold` | `0.5` (threshold mode only) |
| `keepResultTokens` | `12000` |
| `keepCallTokens` | `4000` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `compactionTimeoutMs` | `15000` |
| `builtinFallback` | `auto` |
| `targetPercent` | `45` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `maxConcurrentRequests` | `4` |
| `truncateHeadChars` | `300`, `100` once old prose is digested |
| `dropCalls` | `false` |
| `ageCutResults` | `false` |
| `questionCriteria` | `false` |
| `trimHostText` | `true` |
| `hostTextHeadChars` | `200` |
| `oldProse` | unset: `keep`, then `digest` (`summarize`) |
| `recentTurns` | `8` |
| `proseModel` | `haiku` (`summarize` only) |
| `taskResultHeadChars` | `4000` |
| `baseUrl` | the provider's endpoint |
| `envFile` | unset |

The key can be supplied as the sensitive `apiKey` plugin option, or through
`TYPESAFE_API_KEY` or `OPENROUTER_API_KEY` in the environment, in the settings'
`env` block, or in the dotenv file `envFile` names. The environment variable is
the recommended development setup; `envFile` is for a key that should not sit in
a settings file.

`provider: "openai"` sends the same questions to OpenAI's Decisions API
(`https://api.openai.com/v1/decisions`, `gpt-6-luna`) instead of Jev: the state
goes as the text `input`, each question as a named `predicate`, and the key
comes from `OPENAI_API_KEY` (environment, settings `env`, or `envFile`). The
`apiKey` and `baseUrl` options belong to Jev and are ignored with `openai`, so a
TypeSafe key or a Jev gateway never receives an OpenAI request. A refusal keeps
the call. Luna's probabilities are on a different scale from Jev's, so
`keepThreshold` and the rank budgets may need retuning.

`provider: "algorithmic"` asks no model and needs no key. Each older call is
scored from the transcript alone, after the ranking in
[pi-vcc](https://github.com/sting8k/pi-vcc) and the error tracking in
[pi-blackhole](https://github.com/k0valik/pi-blackhole): recency; a Read of a
file a later edit changed, a call repeated later with the same input, and an
older TodoWrite score near 0; an error a later call resolved scores low, one
still open keeps its result; search output halves, test and build output gains;
state-changing git and gh calls keep their call. The same rank budgets then
decide what stays whole, so the rest of the plugin (cut notes, recall, the
digest, the guards) works as with a model.

`baseUrl` is unset by default, which reaches
`https://api.typesafe.ai/v1/systemone` as before. Set it to
`https://openrouter.ai/api/alpha/decisions` with `model` left at `jev-latest` to
reach the same Jev model through OpenRouter. `envFile` is read only when nothing
earlier held a key, and a file that cannot be read is not an error: the key is
simply not there, and the hook falls back as it would.

Every option except `apiKey`, `baseUrl`, `envFile`, `compactAtPercent`,
`minReductionRatio`, `compactionTimeoutMs`, `builtinFallback`, `targetPercent`
and `model` is passed straight to the library; see
[docs/library.md](../docs/library.md#options) for what they do. The
`session.compact` hook runs the Jev requests concurrently.

The size guards (`minReductionRatio`, `targetPercent`) exist to keep automatic
compactions from running back to back, so a `/compact` the person typed is
applied whenever it frees anything: the attempt that freed the most is
installed, even when a later attempt fails. The `/compact` this plugin queues in
a headless session carries the args `automatic, from jetcompact`, which mark it
as automatic: the guards apply, and the marker is not passed to Jev or the
built-in summarizer as an instruction.

If Jev fails, the response is malformed, the key is unavailable, the history
cannot be fitted into the state budget, or an automatic compaction is refused by
the guards, what happens next depends on the compaction's `trigger`. With
`builtinFallback` at `auto`, only Claude Code's own compaction (`auto`: its
threshold, or a prompt too long, when the conversation has to shrink) and the
plugin's queued one log a fallback and delegate to Claude Code's built-in
compaction; `/compact` (`manual`), another plugin's request (`plugin`) and
`precompute` answer `{ skip }` instead, so the conversation stays as it is and
Claude Code shows why. `always` delegates on every trigger; `never` on none.
When the built-in summary itself fails, the hook installs its own result if that
freed anything. When Claude Code moves on (Esc, the hook's time budget, another
hook settling first), the in-flight request is abandoned and nothing is returned
or delegated. A result Claude Code refuses is logged, and the built-in summary
runs only where `builtinFallback` allows it. The outcome is shown as a one-line
toast. The debug log (`$.ui.log` with `to: 'debug'`, nothing in the transcript)
gets the reduction, per-reason counts, state size and request count, and a
per-call `decisions:` line with both probabilities for diagnosis. The debug log
exists only under `claude --debug`, so each outcome is also appended as one
timestamped line, labelled with the trigger, to
`~/.claude/jetcompact/compactions.log` (under `CLAUDE_CONFIG_DIR` when set; the
newest 200 lines are kept), together with each `/compact` the hook queues in a
headless session. Text typed after `/compact` goes into Jev's goal as what the
user asked the compaction to keep (the first 2000 characters).

Kept messages go back without their engine handle, so `--resume` starts at the
compaction (#89). A message without its handle loses the hidden entries Claude
Code keeps beside it: a skill's body, a prompt typed while a tool ran, file
attachments, images and deferred tools inside results. The hook reads them from
the conversation's API form (`$.session.messages({ as: 'api' })`) and folds them
back as text after the tool result or prompt they followed; images and
ToolSearch-loaded tools become one-line placeholders. Left out: the session
context ahead of the first prompt (environment, CLAUDE.md, skill and tool lists)
and the reminders Claude Code sends again after a compaction or each step (token
countdown, output style, task-tool nudge, deferred tool list, MCP server
instructions), and reminders about a moment that has passed (editor diagnostics,
a file changed on disk, a silence nudge). A message you typed mid-turn and a
background task's result are kept. Such stale reminders already in the rows,
from an earlier compaction, are removed and counted as reduction. The outcome
line counts what was folded back and what was dropped. In a long desktop session
these reminders were 102k of 127k folded characters. Checked live on Claude Code
2.1.296: without the fold a skill body was gone after compaction; with it the
model still had it.

The `turn.complete` hook requests compaction when the context reaches
`compactAtPercent` of the window Claude Code compacts at, with an in-flight
guard. That window is the summary breakdown's `rawMaxTokens`
(`$.session.usage({ breakdown: 'summary' })`, estimated locally, no request):
`CLAUDE_CODE_AUTO_COMPACT_WINDOW` or a setting when one is set, else the
model's. `context.percent` alone counts against the model's whole window, so on
a 1M model, or with a smaller compaction window, it would trigger late. When
that request is skipped, the hook waits until the context has grown by another
10 percentage points, or dropped below `compactAtPercent` again, before it asks
again. Headless sessions (the desktop app's Code tab, `claude -p`) refuse
`$.session.compact`, so there the hook queues `/compact` for when the turn is
over and applies the same wait, since a queued compaction's outcome does not
come back to it. Toasts are not shown in those sessions; the outcome is in the
compaction log.

`targetPercent` guards against a post-compaction floor that rises each time
while old prose is kept verbatim. The hook estimates the context percentage
after compaction, of the same window: the share that is not messages (system
prompt, tools, memory files) stays, and the messages shrink by chars after /
chars before.

With `oldProse` unset, a result that falls below `minReductionRatio` or above
`targetPercent` is computed again with old prose digested and cut results kept
to `truncateHeadChars` (100 unless set), when the history has turns older than
`recentTurns`. Both passes share one `compactionTimeoutMs`. A conversation that
already holds a digest starts with it. When the digest is refused too, or
`oldProse` is set, the result is given up: built-in summary on automatic
compactions, skip otherwise. The outcome line, and the reason of a refusal or
timeout in the second pass, say that verbatim prose was refused first. What the
digest keeps, its trade-offs and the options that control it:
[Adaptive prose digest](../README.md#adaptive-prose-digest).

The hook waits at most `compactionTimeoutMs` for the Jev round, across all
request batches. On a timeout, a plugin-triggered compaction returns a skip
notice and leaves the conversation unchanged; any other compaction is treated
like a Jev failure and follows `builtinFallback` (by default only Claude Code's
own automatic compaction falls back to the built-in summary). This bounds the
Jev wait, not the duration of a built-in summary. The host HTTP interface does
not expose per-request cancellation, so in-flight requests may still finish;
their late results cannot replace the conversation. Zero, negative and
non-finite timeout values use the default.

Run `npm run test:hooks:host` with a function-hook-capable Claude Code CLI to
exercise the deadline through Claude Code's actual hook dispatcher and a virtual
clock. The tests use synthetic messages and mocked HTTP responses and make no
model requests. `npm test` continues to run the fast library and adapter tests
without a Claude CLI.

## Recall

With `recall` on (the default), the plugin registers `recall` with
`$.tool.register` at `session.start`; the model calls it as
`mcp__jetcompact__recall`, kept in the prompt's tool list rather than behind
ToolSearch (see [What the model is told](#what-the-model-is-told)). A compaction
never deletes from the session transcript,
`<config dir>/projects/<project>/<session>.jsonl`: it appends a boundary and
writes the kept messages again. The `tool.call` hook runs `src/recall/cli.ts`
with the pinned Node of `tools/node.cmd` (see
[tools/README.md](../tools/README.md); the first compaction of a session has it
downloaded in the background), which reads the transcript at any size, skips the
copies after each boundary, and keeps each call's first, uncut result:

- `query`: keywords ranked by BM25, or a regex when the query holds regex
  characters. A regex that could backtrack without end (a quantified group, a
  back reference, more than two unbounded quantifiers) is matched as literal
  text, and a regex that finds nothing is ranked as keywords. 5 hits per page,
  each with the lines around its first match.
- `expand`: up to 10 entries in full by `#N` or tool_use_id (a tool_use_id is
  stable; `#N` can shift as the session grows); a call shows its input and its
  result, or the file Claude Code saved a large output to (only from
  `<config dir>/projects/<project>/<session>/tool-results/`: the path comes from
  result text, which fetched content can forge). Long text is cut at a line end
  with an `offset` to continue from.
- `range`: entries `#from..#to`, one line each, 20 per page.
- `touched`: `true` lists the files Edit, Write, MultiEdit and NotebookEdit
  changed, newest change first, with the last five calls on each; a part of a
  path lists every call on the files it matches, reads included. 50 lines per
  page.
- `sessions`: keywords searched in the other sessions of this project (the
  folder under `<config dir>/projects/` that holds this session), or with
  `project: "<part of a folder name or working directory>"` in other projects,
  `project: "all"` in every one. A session counts when it holds every keyword
  (any keyword when none holds all); ripgrep picks those transcripts when it is
  on the PATH, and only their matching lines are read, for at most 30 s. A query
  of only stopwords or single characters is refused. This session is not among
  the results, since `query` searches it live and in full; when the searched
  projects include it, a last line counts its matches
  (`Also in this session: <n> matches; …`). Hits are numbered by rank and
  labelled with the project, the date, the session title (or first prompt) and
  the session id; open one with `session`. With qmd installed and
  `sessionIndex: "auto"` (the default), the search goes through a qmd index
  instead: each transcript is exported as markdown to
  `<config dir>/jetcompact/sessions/<project>/<session>.md` (prompts, replies,
  calls with the head of their results) and indexed in a qmd index of its own,
  `jetcompact-sessions` (`~/.cache/qmd/jetcompact-sessions.sqlite`,
  `~/.config/qmd/jetcompact-sessions.yml`), apart from the default one. The
  first search builds it in the background and is answered by the scan; later
  searches re-export the sessions that changed (not the current one), update the
  index and search it. When the index finds nothing in the asked projects, or a
  search fails or throws, the scan answers; a failed search rebuilds the index
  next time only when its index file is gone. The exports, their folders and the
  index file are made readable by their owner only on each build, and an export
  goes when Claude Code removes its transcript after `cleanupPeriodDays`. On
  Windows the npm `qmd.cmd` shim is run as its script under the shim's own Node.
  `sessionIndex: "off"` always scans. `/recall-index` builds, shows or removes
  that index on demand (below).
- `session: "<id or its first 8+ characters>"` runs `query`, `expand`, `range`,
  `touched` or `agent` on that session instead of this one.
- `agent`: subagents keep their own transcripts under `<session>/subagents/`.
  `"list"` names them with the Agent call that started each; a part of an
  agent's id or name runs the request on that agent's transcript, `"all"` on the
  session's and every agent's. Subagent entries are numbered per agent, in the
  order the session started them: the first agent's from #100001, the second's
  from #200001, so their numbers hold while the session grows. `expand` finds a
  subagent entry by that number or a call by its tool_use_id without `agent`,
  and an Agent call shows the agent it started.

An answer holds at most 48,000 characters, shared between expanded entries.
Recall's own calls are not listed. Cut notes end with
`full text: recall expand ["<tool_use_id>"]` instead of telling the model to run
the tool again. Recall reads what the transcripts hold, until Claude Code
removes old ones after `cleanupPeriodDays`; the only copies are the session
index's exports above. The ranking and regex mode are adapted from
[pi-vcc](https://github.com/sting8k/pi-vcc), the answer budget from
[pi-blackhole](https://github.com/k0valik/pi-blackhole) (both MIT).

### What the model is told

With `recall` on, the model learns about compaction and recall where it needs
to, and never on every prompt:

- **The tool stays loaded.** The hook answers `tool.describe` for recall with
  `isDeferred: false`, so its description sits in the prompt's tool list instead
  of behind ToolSearch, where the model sees only the name. The description does
  not change, so the prompt cache keeps it.
- **Each cut note** names the call that returns the rest:
  `full text: recall expand ["<tool_use_id>"]`.
- **A digest or summary header** ends with
  `the recall tool reads them back from the transcript (query, expand)`.
- **One compaction note** opens the compacted history: a user message starting
  `[jetcompact note]` that says what this compaction cut (results cut to heads,
  calls stubbed or dropped, messages digested) and to use recall before running
  a tool again or saying something earlier is gone, with an assistant
  acknowledgement. Each compaction replaces it, so there is only ever one; a
  compaction that cut nothing writes none. It is part of the conversation, so it
  survives a restart and `--resume`, until Claude Code's built-in summary
  replaces the history.

### `/recall-index`

With `recall` on, the plugin adds the slash command `/recall-index`, which
builds, shows or removes the session index on demand instead of waiting for the
first cross-session search to build it in the background:

| Command | Does |
| -- | -- |
| `/recall-index` or `/recall-index status` | Which projects the index covers, how many sessions are exported, the index size and when it was last built |
| `/recall-index all` | Indexes every project's sessions now |
| `/recall-index <project>…` | Indexes these projects now, added to the ones it covers |
| `/recall-index remove <project>…` | Takes these projects out of the index |
| `/recall-index remove` or `remove all` | Deletes the exports, the index and its qmd collection |

A project is named by any part of its folder name (`billing`), by its path in
any slash style or case (`C:\work\app`, `c:/WORK/app/`), by `~/…`, by a path
relative to this session's project, or by `.` for this session's project. A
folder takes every project under it: `/recall-index C:\work` indexes all
projects in `C:\work`. Separate several with spaces or commas, and quote a path
that has spaces. A name that matches nothing is reported, and nothing is built
for it.

The command waits for the build and reports what it did, for example
`Indexed <n> sessions in <m> projects (<names>) in <seconds> s; index <size>.`.
Once projects are chosen, later searches keep only those up to date; a search in
any other project scans its transcripts. An index the first search built for all
projects keeps covering all of them. Without qmd the command says how to install
it (`npm install -g @tobilu/qmd`); recall never installs it.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.292 in
`types/claude-code.d.ts`; regenerate and review that file after a Claude Code
upgrade.
